# ระบบเช็กชื่อ นศท. — รุ่น 1.0

เว็บภาษาไทยสำหรับ GitHub Pages + Supabase ใช้ได้ทั้งโทรศัพท์และคอมพิวเตอร์

## เปิดดูทันที

เปิด `Demo.html` เพื่อทดลองด้วยข้อมูลสมมติ ไม่ต้องติดตั้งโปรแกรมและไม่ต้องใช้บัญชี Supabase ข้อมูลทดลองเก็บในเบราว์เซอร์เครื่องนั้น การเปิดโหมดจริงจะเริ่มจากทะเบียนว่าง

อ่าน `Install.html` สำหรับขั้นตอนติดตั้งแบบละเอียด

## ฟังก์ชัน

- Dashboard แยกปีการศึกษาและชั้นปี 1–3
- Sidebar ยุบเหลือไอคอนบนคอมพิวเตอร์และจำสถานะ บนมือถือใช้ปุ่ม ☰
- เช็ก “มา / ขาด” เท่านั้น ไม่มีการตั้งขาดอัตโนมัติ รายการที่ยังไม่บันทึกแยกไว้เสมอ
- สร้างรอบฝึก วันที่ ช่วงเวลา หัวข้อ และชั่วโมง บันทึกบางรายได้
- เก็บผู้เช็กและเวลาฝั่งฐานข้อมูล พร้อมตรวจรุ่นข้อมูลเพื่อป้องกันการเขียนทับจากหลายคน
- ทะเบียนรายปี เพิ่มคนเดียวหรือนำเข้า .xlsx / .csv พร้อมตรวจทุกแถวก่อนนำเข้าทั้งชุด
- แบบฟอร์ม Excel และรายงาน Excel ทั้งสรุปรายบุคคลและรายรอบ พิมพ์เป็น PDF จากเบราว์เซอร์
- ผลการฝึกกำหนดโดยผู้ดูแล ไม่ตัดสินผ่าน/ไม่ผ่านจากเปอร์เซ็นต์อัตโนมัติ
- เลื่อนชั้นตามผลการฝึก: ผ่านปี 1–2 เลื่อนหนึ่งชั้น, ไม่ผ่านอยู่ชั้นเดิม, ผ่านปี 3 สำเร็จการฝึก
- เลื่อนชั้นด้วยการยืนยันครั้งเดียวทั้งปี พร้อมสร้างปีถัดไปและปิดปีเดิม เก็บประวัติเดิมครบ
- สิทธิ์ admin / teacher / viewer และ Audit log
- ดาวน์โหลดสำเนาข้อมูล JSON; มี GitHub Actions สำหรับสำรองฐานข้อมูลเข้ารหัสทุกวันเมื่อกำหนดค่าแล้ว

## ติดตั้งโดยสรุป

1. สร้าง Supabase project ใหม่และรัน `supabase/schema.sql` ครั้งเดียว
2. สร้างบัญชีแรกใน Authentication > Users แล้วแก้อีเมลและรัน `supabase/bootstrap-admin.sql`
3. ปิดการสมัครสมาชิกสาธารณะใน Authentication Settings (ระบบนี้ให้ผู้ดูแลสร้างบัญชี)
4. ใส่ URL และ Publishable key หรือ legacy anon key ใน `web/config.js`
5. อัปโหลดโครงสร้างทั้งหมดขึ้น repository ใหม่บน GitHub แล้วเปิด Settings > Pages > Source: GitHub Actions
6. ติดตั้ง Edge Function `manage-users` และตั้งค่า `ALLOWED_ORIGINS` ตามคู่มือ
7. ตั้ง GitHub Secrets สำหรับสำรองข้อมูล และทดสอบ workflow ด้วย Run workflow หนึ่งครั้ง
8. เปิดเว็บ ล็อกอิน สร้างปีการศึกษา และนำเข้ารายชื่อจริง

หน้าเว็บใช้ได้โดยไม่ต้องรันเซิร์ฟเวอร์บนคอมพิวเตอร์ของครู แต่ต้องใช้อินเทอร์เน็ตขณะใช้งานจริง

ตรวจสิทธิ์ในฐานข้อมูลและ Edge Function ด้วย ไม่ได้อาศัยการซ่อนปุ่มเท่านั้น ผู้ใช้เปลี่ยน role ของตนเองด้วยการเรียกตารางตรงไม่ได้ บัญชีที่ยังไม่เปิดสิทธิ์ไม่เห็นข้อมูลนักศึกษา

## การนับข้อมูล

“ยังไม่บันทึก” คือไม่มีแถวการเช็กชื่อสำหรับนักศึกษาคนนั้นในรอบที่เกี่ยวข้อง ฐานข้อมูลเก็บเฉพาะ present / absent การคืนเป็นยังไม่บันทึกจะลบแถวสถานะและมีประวัติใน Audit log

อัตราเข้าฝึก = มา ÷ (มา + ขาด) × 100 ไม่นับยังไม่บันทึกในตัวหาร ถ้าไม่มีรายการที่บันทึกเลยให้แสดง — ชั่วโมงสะสมรวมเฉพาะรอบที่มา และไม่นับรอบก่อนวันเริ่มนับของนักศึกษา

ข้อมูลปีเก่าปิดแก้ไขหลังเลื่อนชั้น โรงเรียนต้องระบุผลการฝึกจริงก่อนดำเนินการ ระบบไม่เลื่อนชั้นเองเมื่อถึงวันที่กำหนด และไม่เดาเกณฑ์ผ่านการฝึก

## การสำรองและกู้ข้อมูล

workflow สำรองจะทำงานประมาณ 02:17 น. ประเทศไทย เก็บไฟล์ฐานข้อมูลที่เข้ารหัส 30 วันใน GitHub Actions artifact และต้องตั้ง Secrets ก่อนจึงทำงานได้ ตารางเวลา GitHub อาจคลาดเคลื่อน และ repository สาธารณะอาจหยุด schedule หลังไม่มีความเคลื่อนไหวเป็นเวลานาน จึงต้องตรวจผล workflow เป็นระยะ

ตั้ง `SUPABASE_DB_URL` เป็น PostgreSQL connection string แบบ Session pooler (port 5432) พร้อม `sslmode=require` และ `BACKUP_PASSPHRASE` เป็นข้อความลับสุ่มยาวอย่างน้อย 24 ตัวอักษร เก็บสำเนาข้อความลับไว้นอก GitHub ด้วย

การดาวน์โหลด JSON จากหน้าเว็บไม่รวมรหัสผ่าน และไม่ใช่ไฟล์สำรอง Supabase ทั้งระบบ การกู้ JSON ทำได้โดยผู้ดูแลฐานข้อมูล ส่วน workflow สำรอง public/private/auth รวมบัญชีเพื่อใช้เป็นข้อมูลกู้คืน แต่ไม่รวม Supabase platform configuration, Secrets หรือไฟล์ Storage (แอปรุ่นนี้ไม่ได้ใช้งาน Storage)

หากต้องกู้ฐานข้อมูล ให้ดาวน์โหลด artifact ถอดรหัสด้วย GPG ในเครื่องผู้ดูแล แล้วให้ผู้ดูแลฐานข้อมูลใช้ `pg_restore` ตรวจรายการในฐานข้อมูลทดสอบก่อนกู้ลงระบบจริง ห้ามเปิด `.dump` หรือไฟล์ JSON ต่อสาธารณะ และอย่ารัน schema.sql ซ้ำบนฐานข้อมูลที่มีระบบนี้แล้ว

## ตรวจสอบก่อนใช้งานจริง

- รัน `npm test` สำหรับกฎการนับและไฟล์นำเข้า
- `tests/database.test.mjs` ทดสอบ SQL/RLS ด้วย PGlite แบบแยกจากข้อมูลจริง: ตั้ง `PGLITE_PATH` เป็นพาธของแพ็กเกจ PGlite ที่ติดตั้ง แล้วรันไฟล์นี้ด้วย Node
- ผลที่ตรวจในชุดส่งมอบ: 8 กรณีกฎข้อมูล และ 16 กรณีฐานข้อมูล ผ่านทั้งหมด
- ตรวจในเบราว์เซอร์แล้ว: Dashboard, เมนูมือถือ, เช็กบางรายและบันทึกโดยคนที่เหลือยังไม่บันทึก, นำเข้า Excel และดาวน์โหลดรายงานจริงในโหมดทดลอง
- ยังไม่ได้ตรวจการล็อกอินกับ Supabase จริง, Edge Function ที่ deploy แล้ว หรือ GitHub Actions เพราะยังไม่ได้ระบุโปรเจคและ repository ปลายทาง
- อย่าอ้างว่าสำรองอัตโนมัติเปิดแล้ว จนกว่าจะมี workflow สำเร็จและดาวน์โหลดถอดรหัสทดสอบได้
