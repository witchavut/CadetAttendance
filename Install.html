เปิดทดลองก่อนได้ทันที

ดับเบิลคลิก Demo.html เพื่อทดลองระบบโดยไม่ต้องติดตั้งอะไร ข้อมูลที่เห็นเป็นรายชื่อสมมติ และเก็บเฉพาะเบราว์เซอร์นี้

ลองกดเช็กชื่อ “มา” หรือ “ขาด” บางรายแล้วบันทึก คนที่เหลือจะยังเป็น ยังไม่บันทึก และไม่นับขาดอัตโนมัติ

ไฟล์ Demo ใช้ทดลองเท่านั้น การใช้ข้อมูลจริงร่วมกันหลายเครื่องต้องทำขั้นตอนติดตั้งด้านล่าง ขณะส่งมอบยังไม่ได้ผูกบัญชี Supabase หรือเผยแพร่ไป GitHub ของคุณ
STEP 01

สร้างฐานข้อมูล Supabase

  1. เข้า Supabase Dashboard สมัครหรือเข้าสู่ระบบ แล้วเลือก New project
  2. ตั้งชื่อ เช่น cadet-attendance กำหนดรหัสผ่านฐานข้อมูล และเลือกภูมิภาคใกล้ประเทศไทย แล้วรอจนโปรเจคพร้อม
  3. เปิดเมนู SQL Editor → New query
  4. เปิดไฟล์ supabase/schema.sql ด้วย Notepad หรือ VS Code คัดลอกเนื้อหาทั้งหมดวางใน SQL Editor แล้วกด Run
  5. เมื่อสำเร็จ จะมีตาราง profiles, academic_years, students, enrollments, training_sessions, attendance, audit_logs
ใช้กับโปรเจคใหม่ และรัน schema.sql เพียงครั้งเดียว ไฟล์นี้ตั้งสิทธิ์และสร้างกฎข้อมูล ไม่ได้ใส่รายชื่อนักศึกษาตัวอย่างลงฐานข้อมูลจริง
STEP 02

สร้างบัญชีผู้ดูแลคนแรก

  1. เปิด Supabase → Authentication → Users → Add user / Create user
  2. ใส่อีเมลของคุณและรหัสผ่านที่คุณกำหนดเอง เลือกยืนยันอีเมลอัตโนมัติถ้ามีตัวเลือก
  3. เปิดไฟล์ supabase/bootstrap-admin.sql แล้วเปลี่ยน CHANGE_TO_YOUR_EMAIL@example.com เป็นอีเมลที่เพิ่งสร้าง
  4. นำโค้ดที่แก้แล้วไปรันใน SQL Editor เพื่อเปิดสิทธิ์ admin
  5. ใน Authentication Settings ปิดการสมัครสมาชิกใหม่แบบสาธารณะ ระบบนี้ให้ผู้ดูแลสร้างบัญชีครูจากหลังบ้าน
ไม่มีรหัสผ่านผู้ดูแลสำเร็จรูปฝังอยู่ในระบบ คุณเป็นผู้ตั้งรหัสเองใน Supabase
STEP 03

เชื่อมหน้าเว็บกับฐานข้อมูล

  1. ใน Supabase เปิด Project Settings → API / API Keys หรือเมนู Connect
  2. คัดลอก Project URL และ Publishable key (หรือ legacy anon key)
  3. เปิดไฟล์ web/config.js แล้วใส่ค่าลงระหว่างเครื่องหมายคำพูด
window.CADET_CONFIG = {
  supabaseUrl: 'https://รหัสโปรเจคของคุณ.supabase.co',
  supabaseKey: 'ใส่ Publishable key หรือ anon key',
  schoolName: 'โรงเรียนเมืองกาฬสินธุ์',
};
ใช้เฉพาะ Publishable / anon key ในหน้าเว็บ เพราะสิทธิ์ข้อมูลจะถูกตรวจที่ฐานข้อมูล ห้ามนำ secret key, service_role key หรือรหัสผ่านฐานข้อมูลมาใส่ใน config.js หรือ GitHub source
STEP 04

เผยแพร่ด้วย GitHub Pages

  1. เข้าสู่ GitHub แล้วสร้าง repository ใหม่ เช่น CadetAttendance
  2. อัปโหลดไฟล์ในโฟลเดอร์โปรเจค โดยให้มี web/, supabase/ และ .github/ อยู่ที่ระดับบนสุดของ repository ไม่ซ้อนอยู่ในโฟลเดอร์ชื่อโปรเจคอีกชั้น
  3. ตรวจว่ามีไฟล์ .github/workflows/pages.yml และ web/index.html อยู่จริง และ branch หลักชื่อ main
  4. เปิด Settings → Pages → Build and deployment → Source เลือก GitHub Actions
  5. เปิด Actions → Publish attendance website → Run workflow แล้วรอจนสำเร็จ หากรันครั้งแรกก่อนเปิด Pages แล้วไม่ผ่าน ให้รันใหม่หลังตั้งค่าแล้ว
  6. เปิดลิงก์ที่แสดงในหน้า Pages หรือผล Deploy ตัวอย่างรูปแบบ URL คือ https://ชื่อบัญชี.github.io/CadetAttendance/

การใช้ GitHub Pages จาก repository ส่วนตัวขึ้นอยู่กับแพ็กเกจ GitHub ที่ใช้อยู่ ให้ตรวจตัวเลือกในบัญชีของคุณก่อนเลือกชนิด repository

GitHub Pages เผยแพร่เฉพาะโฟลเดอร์ web ส่วนข้อมูลนักศึกษาอยู่ใน Supabase ผู้เข้าหน้าเว็บต้องล็อกอินและมีสิทธิ์ก่อนดูข้อมูลจริง
STEP 05

เปิดใช้หลังบ้านเพิ่มผู้ใช้

ส่วนนี้ใช้ Edge Function เพื่อสร้างบัญชี โดยเก็บสิทธิ์ admin ของ Supabase ไว้ที่ฝั่งเซิร์ฟเวอร์

  1. ใน Supabase เปิด Edge Functions สร้าง function ชื่อ manage-users
  2. ใส่โค้ดทั้งหมดจาก supabase/functions/manage-users/index.ts
  3. ตั้งค่า Verify JWT เป็นปิดสำหรับ function นี้ตาม supabase/config.toml เพราะตัวโค้ดตรวจ bearer token กับ Auth และตรวจ role ในฐานข้อมูลเองก่อนทำงานทุกครั้ง
  4. ใน Edge Functions → Secrets เพิ่ม ALLOWED_ORIGINS เช่น https://ชื่อบัญชี.github.io ใช้เฉพาะ origin ไม่ใส่ชื่อ repository ต่อท้าย ถ้ามีหลาย origin ให้คั่นด้วย comma
  5. ค่า SUPABASE_URL, SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY เป็น environment ที่ Supabase จัดให้ อย่านำค่า service role ไปใส่หน้าเว็บ
  6. Deploy function แล้วล็อกอินเว็บด้วย admin เข้าเมนู ผู้ใช้และสิทธิ์ → เพิ่มผู้ใช้ สร้างบัญชีทดสอบและลองล็อกอิน
สิทธิ์ทำอะไรได้
ผู้ดูแลระบบจัดการทุกส่วน รวมผู้ใช้ ผลการฝึก เลื่อนชั้น และสำรองข้อมูล
ครูผู้เช็กชื่อดูทะเบียน รายงาน สร้างรอบฝึก และบันทึกเช็กชื่อ
ผู้ดูรายงานดูข้อมูลและดาวน์โหลดรายงาน

หากยังไม่ติดตั้ง function บัญชี admin แรกยังใช้ระบบหลักได้ แต่การเพิ่มบัญชีใหม่จากหน้าเว็บยังไม่ทำงาน

STEP 06

ตั้งสำรองฐานข้อมูลอัตโนมัติ

มี workflow สำหรับสำรองแบบเข้ารหัสให้ทุกวันประมาณ 02:17 น. ประเทศไทย แต่ยังไม่ทำงานจนกว่าจะใส่ Secrets และทดสอบสำเร็จ

  1. ใน GitHub repository เปิด Settings → Secrets and variables → Actions → New repository secret
  2. เพิ่ม SUPABASE_DB_URL โดยใช้ connection string แบบ Session pooler port 5432 จาก Supabase → Connect ใส่รหัสผ่านฐานข้อมูลให้ครบและใช้ sslmode=require
  3. เพิ่ม BACKUP_PASSPHRASE เป็นข้อความลับสุ่มยาวอย่างน้อย 24 ตัวอักษร เก็บสำเนาไว้นอก GitHub ด้วย
  4. เปิด Actions → Encrypted daily database backup → Run workflow
  5. เมื่อสำเร็จ ดาวน์โหลด artifact จากหน้านั้น จะได้ไฟล์ cadet-db.dump.gpg เก็บย้อนหลัง 30 วัน ต้องถอดรหัสได้จึงถือว่าทดสอบสำรองสำเร็จ
Supabase แพ็กเกจ Free ไม่ได้มี daily backup ให้อัตโนมัติ ส่วนแพ็กเกจเสียเงินมีนโยบายสำรองตามแพ็กเกจ ตรวจรายละเอียดได้ที่ เอกสาร Supabase workflow ที่แนบเป็นทางสำรองแยกจากบริการนั้น

ตรวจผล workflow เป็นระยะ ตารางรันของ GitHub อาจคลาดเคลื่อน และ schedule ใน repository สาธารณะอาจหยุดเมื่อไม่มีความเคลื่อนไหวนาน ระหว่างนี้ใช้ปุ่ม ดาวน์โหลดสำเนาข้อมูลทั้งหมด ในหน้าเว็บได้อีกทาง

กรณีต้องกู้ข้อมูล

ไฟล์ JSON จากหน้าเว็บเป็นสำเนาข้อมูลแอป ไม่รวมรหัสผ่าน ส่วนไฟล์จาก workflow รวม schema และข้อมูล public/private/auth ถอดรหัสด้วย GPG และให้ผู้ดูแลฐานข้อมูลใช้ pg_restore ทดสอบในฐานข้อมูลแยกก่อนกู้จริง ไฟล์สำรองไม่รวม Secrets และการตั้งค่าของแพลตฟอร์ม

STEP 07

เริ่มใช้งานจริง

  1. เปิดลิงก์เว็บแล้วล็อกอินด้วยบัญชี admin ที่สร้างไว้ ตรวจว่ามุมบนแสดง เชื่อมต่อฐานข้อมูลจริง
  2. เข้า ปีการศึกษา / เลื่อนชั้น → เพิ่มปีการศึกษา เช่น 2569 และกำหนดวันเริ่มปี
  3. เข้า นำเข้า Excel ดาวน์โหลดแบบฟอร์ม กรอกในชีต ทะเบียน แล้วนำเข้าหลังตรวจข้อมูลถูกต้อง
  4. เข้า เช็กชื่อการฝึก เลือกชั้นปี กดสร้างรอบฝึก และระบุมา/ขาดตามจริง กดบันทึก
  5. ดูภาพรวมและดาวน์โหลดรายงานได้ทันที ชั่วโมงคิดเฉพาะรอบที่มา อัตราคิดจาก มา ÷ (มา + ขาด)
  6. สิ้นปีให้กำหนดผลการฝึกในทะเบียนแต่ละคน จากนั้นตรวจตารางก่อนกดเลื่อนชั้นทั้งปี ระบบจะสร้างทะเบียนใหม่ตามผลและปิดปีเดิม
ยังไม่บันทึกไม่เท่ากับขาด · ผลผ่าน/ไม่ผ่านกำหนดโดยผู้รับผิดชอบ · ประวัติปีเดิมยังเปิดดูได้

หากเปิดใช้งานไม่สำเร็จ

อาการตรวจตรงไหน
ยังเห็นโหมดทดลองconfig.js ต้องใส่ URL และ key ให้ครบ และอัปโหลดขึ้น GitHub แล้ว
เข้าสู่ระบบไม่ได้ตรวจ Authentication > Users, อีเมล, รหัสผ่าน และการยืนยันอีเมล
บัญชียังไม่เปิดสิทธิ์รัน bootstrap-admin.sql สำหรับบัญชีแรก หรือให้ admin เปิดสิทธิ์จากหลังบ้าน
เพิ่มผู้ใช้ไม่ได้ตรวจ Edge Function, Verify JWT, ALLOWED_ORIGINS และผล Deploy
เช็กชื่อแล้วแจ้งมีคนแก้ไขโหลดข้อมูลใหม่ก่อนเลือกสถานะและบันทึกอีกครั้ง ระบบป้องกันข้อมูลทับกัน
เลื่อนชั้นไม่ได้กำหนดผลให้ครบทุกคน ปีปลายทางต้องเป็นปีถัดไปและยังไม่มีอยู่
backup ไม่ผ่านตรวจ Secrets, pooler URL/รหัสผ่าน และ error ใน Actions โดยไม่เผยแพร่ secret ในแชตหรือ source

ชุดส่งมอบนี้ตรวจตรรกะ 8 กรณีและฐานข้อมูล 16 กรณีแล้ว รวมทั้งหน้าจอคอมพิวเตอร์ มือถือ การนำเข้า Excel และดาวน์โหลดรายงาน ยังต้องทดสอบการเชื่อมต่อกับ Supabase/GitHub จริงหลังตั้งค่าปลายทาง
